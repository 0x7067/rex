# rex v0.1.0-alpha.2

## Highlights

- Reduced noisy local embedding startup logs during successful indexing.
- Added overflow-safe chunk re-splitting for token-dense files before embedding.
- Preserved retrieval and `rex ask` behavior for split chunks with line-aware citations.
- Updated onboarding and release documentation to reflect the current `node-llama-cpp` embedding runtime.

## What Changed

### Local embeddings

- `rex` still uses the local GGUF `nomic-ai/nomic-embed-text-v1.5` embedding path through `node-llama-cpp`.
- Successful runs now suppress warn-level llama startup chatter while still surfacing real errors.
- The default embedding context remains `4096`.

### Safer indexing

- Dense chunks that would risk overflowing the embedding path are now re-split before embedding.
- Chunk provenance is preserved across split chunks, including file path, line spans, and stable ordering.
- The chunker compatibility marker was bumped, so existing resources may perform a full reindex on the next `rex sync`.

### Query behavior

- Retrieval keeps split chunks in stable order.
- `rex ask` continues to pass split retrieval chunks through to grounded answer generation and line-based source output.

### Documentation

- README onboarding now describes the actual local embedding backend.
- Preflight docs no longer imply Ollama is required for the default Claude-based path.
- Release documentation now points to versioned draft release notes.

## Upgrade Notes

- No CLI commands changed.
- If you already have indexed resources, expect a compatibility-driven reindex on next sync because of the chunker profile bump.
- Ollama remains optional unless you want to use the Ollama answer-provider path.
